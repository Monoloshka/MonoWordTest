# MonoWordTest

A tiny translation-guessing game. Load a `.txt` file where every line looks like

Page generated by Claude AI.

Обновление кода на паузе из-за блокировок и ограничений Claude. Если проблема не решится то будет использованна другая нейросеть.

```
word - translation
```

(the separator is **space, hyphen, space**; a bare `-` inside a word is not a separator),
choose how many answer options you want (2-10) and guess. A wrong answer turns red, the right one
turns green, then the next question comes automatically after a delay you choose, or when you press **Next**.
**To menu** returns to the start screen.
A built-in Russian <-> English dictionary (`dictionary.txt`, embedded via `dictionary.js`) is included.

## Quick start (no build, no compile)

Open **`MonoWordTest.html`** in any browser. It is the whole program in ONE file (dictionary, ads, About data, sounds and the
spreadsheet reader are inside), so it works from any folder, also in sandboxed browsers (Flatpak/Snap Firefox, where only the
single opened file is visible to the browser) and can simply be sent to someone. Languages other than English are imported
with the **+** button (files from `languages/`).

`index.html` + the neighbouring `.js` files are the readable source version (they must stay together in one folder).
After changing anything (ads, about, sounds, dictionary, version ...) run `python3 tools/build_all.py` (or the single tools,
and finally `python3 tools/build_single.py`) and commit the regenerated `MonoWordTest.html` (handy for opening straight from a clone). GitHub Actions never trusts the committed copies: its first job (`prepare`) regenerates `dictionary.js`, `ads.js`, `about.js`, `sounds.js`, the `.po` files and `MonoWordTest.html` from the sources and hands them to all other jobs, so a forgotten regeneration cannot break a build.

## Start screen options

* **Dictionaries:** pick several files at once (**Browse...**) or a whole folder (**Folder...**, where the browser supports it).
  Supported: `.txt` (`word - translation`), and spreadsheets `.xlsx`, `.xls`, `.ods` (Excel / LibreOffice Calc): column A and column B
  of every sheet. All chosen files are merged. The spreadsheet library (`vendor/`, SheetJS, Apache-2.0) is loaded only when a spreadsheet is chosen;
  it is not part of the OpenWrt package.
* **Pictures instead of words:** a side of a line may be a picture reference (`.png .jpg .jpeg .webp .gif .svg`, or an `http(s)://` link), e.g.
  `pics/cat.png - cat`. A local path is relative to the folder of the dictionary file. Select the pictures together with the dictionary
  (or pick the folder). With a plain multi-select the browser does not tell folders, so then the file name alone is matched.
  Pictures are always the question, never an answer option. A picture that cannot be found is shown as its text.
* **Next question:** automatically after N seconds, or by a **Next** button.
* **Count correct and wrong answers** for the current session (from **Start** until **To menu**). A question counts once: wrong if a wrong
  answer was clicked first, otherwise correct.
* **Sound:** `sounds/sounds.txt` maps events (`correct wrong start builtin menu exit`) to `.mp3` files, one file may serve several events.
  Run `python3 tools/build_sounds.py` after editing. The three included files are tiny generated placeholders. If no events are mapped the option is hidden.
* **Exit** (closes the app) appears only in the standalone apps (Electron, NW.js, Android). It is hidden in a browser tab and on OpenWrt.
* **About:** icon (`build/icon.png`), version (`package.json`), author line and a list of links, from `about/about.txt`
  (`python3 tools/build_about.py`). A line without link and icon is plain text. About links can be copied: long-press (touch) or right-click -> **Copy link**.
* When the app comes back to the foreground (Android: minimised and opened again) a new random ad is chosen, if the start screen is showing.

## Languages

The app itself contains **only English**. Other languages are separate `.json` files (folder `languages/`, also published as
`MonoWordTest-<version>-languages.zip`) that the user imports with the **+** button next to the language list - several files at once,
and one file may hold several languages. Imported languages are remembered on that device; **Remove imported languages**
(last item of the list) forgets them. Without any imported file there is just English.

The language is chosen automatically from the system/browser locale (`navigator.languages`) among the available ones,
otherwise English; the user can override it in the list (flag emoji + name). A string missing in a language is shown in English.
If several entries share a language code they are listed as `Русский`, `Русский (2)`, `Русский (3)` ...
(importing exactly the same content twice is ignored).

**Add a language:** copy `languages/template.json`, rename it, set the language code, `name`, `flag` and fill in the right-hand side
of each `"English text": "translation"` line (the left side must stay unchanged; keep `{n}` / `{v}`). Details: `languages/README.txt`.
Language files are only read as data (JSON), never executed. Note: Windows does not draw flag emoji (it shows letters such as "RU");
Android, macOS, Linux and iOS do.

## Theme

Auto (follows the system dark/light setting), Light or Dark - selectable in the top bar and remembered.

## Ads (start screen only)

* Ads are **embedded in the app** (`ads.js`; images as data URIs); nothing is fetched from the internet,
  and there is no user-visible setting for them.
* Shown at the bottom centre of the start screen, in the page flow (never over the UI) and **never during the game**.
  Every time the start screen appears a random ad is chosen again (never the same one twice in a row).
* An ad is either an image banner (PNG recommended) or a plain text link. A click/tap opens the link in the browser.
  The link is deliberately not offered for copying (no context menu, no dragging, no text selection).
  This is a convenience barrier only: the address is still visible in the browser status bar or developer tools.
* A small "Ad" label (translated) is shown above it.
* **OpenWrt packages contain no images at all** (routers have little flash): every ad becomes a plain text link.

**Add / remove an ad:** put the image into `ads/` and add or delete a line in `ads/ads.txt`
(`file | https://link | text`; write `-` instead of the file for a text-only ad), then run
`python3 tools/build_ads.py` and rebuild. Optimize PNGs first (e.g. with FileOptimizer): they are stored as
base64, which adds about 33%. The included samples point to example.com - replace them.
If `ads.txt` has no entries the ad area is not shown.

(Embedded means "not a setting", not tamper-proof: anyone can unpack an APK/asar and edit the files.)

## App icon

Put your icon at **`build/icon.png`** (square PNG, 1024 px). That is the only source: `tools/make_icons.py` derives
everything else from it (`build/icons/16..512.png` for Linux/Flatpak/deb/rpm, and the Android launcher icons incl.
the adaptive/round ones; CI runs it automatically). Flatpak silently drops icons larger than 512 px, which is why
the extra sizes are needed. After installing a new APK over an old one, uninstall the old one or restart the launcher:
Android caches launcher icons.

## Languages in Flatpak (gettext)

Inside a Flatpak the app also gets its languages from the standard gettext location (in addition to files the user imports):
`/app/share/locale/<lang>/LC_MESSAGES/monowordtest.mo` (on the host e.g. `/var/lib/flatpak/app/io.github.monowordtest/x86_64/master/<hash>/files/share/locale/ru/LC_MESSAGES/`).
The English source text is the `msgid`; the language's own name and flag are stored as `X-MWT-Name` / `X-MWT-Flag` header lines.

`python3 tools/make_po.py` (Python only, no gettext tools needed) converts `languages/*.json` into `po/*.po` + `po/monowordtest.pot`
(editable catalogues) and `build/locale/*/LC_MESSAGES/monowordtest.mo`; CI runs it before the Flatpak build and
`package.json` (`build.flatpak.files`) installs `build/locale` to `/app/share/locale`. `languages/*.json` stay the source of truth.
Fallbacks: if the `.mo` files are missing or unreadable, or the app is not in a Flatpak (browser, Android, OpenWrt, Windows ...),
the app simply has English plus the imported language files; a missing string falls back to English.

## Keyboard, zoom, reload, copy

* Answers are numbered; keys 1-9 (and 0 for the 10th) pick one. Browser/app shortcuts with Ctrl/Alt/Meta are never touched.
* Arrow keys move the focus like Tab. A closed drop-down list keeps its own arrow behaviour (changes the value) until its first/last
  item is reached; then the arrow moves on. Number fields keep their arrows. Enter/Space press Browse / Folder.
* Electron app: F5 and Ctrl+R reload, Ctrl+Plus/Minus/0 and Ctrl+mouse wheel zoom, right-click on selected text offers Copy
  (Edit/View menu is hidden; Alt shows it). Normal browsers already do all of this themselves.
  NW.js (XP/Vista): the bridge adds F5/Ctrl+R and Ctrl+wheel zoom.

## Built-in dictionary

`dictionary.txt` is the built-in dictionary (edit it freely). `dictionary.js` is the same text wrapped into a JavaScript string,
because a page opened straight from disk (`file://`) cannot read a neighbouring `.txt`, but it can load a neighbouring script.
After editing the txt run `python3 tools/build_dictionary.py` (CI regenerates it anyway).

## Robustness

Lines without ` - `, empty lines, lines with an empty side and garbage are skipped silently.
Files are read as UTF-8 and re-read as Windows-1251 if invalid UTF-8 is detected.
If the file has fewer distinct answers than requested, the round uses as many as exist.

## Running

Open `index.html` in a browser. Keep the `.js` files next to it.

## Packaging (one codebase, separate build per target)

The app is a static web page, so every target below is a thin wrapper around the same files.
These wrappers are **not included and not tested**; they are the standard routes:

| Target | Route |
|--------|-------|
| Android `.apk` | Capacitor or Cordova (WebView); or PWA/TWA via Bubblewrap |
| Windows `.exe` / `.msi`, macOS `.app` / `.pkg`, Linux `.deb` `.rpm` AppImage Flatpak Snap, AUR, Nix | Tauri, Electron or NW.js; x86_64 and ARM/aarch64 come from the wrapper's target options |
| Windows XP / Vista | NW.js 0.14.x (Chromium 49) is the last line that ran on them |
| Windows 95 / 98 / Me / 2000 | No modern web runtime exists. A native port (e.g. Free Pascal / Lazarus) would be needed |

If a wrapper opens `target="_blank"` links inside the app window, route the banner and badge links to the
system browser (Tauri: `shell.open`, Electron: `shell.openExternal`, Capacitor: `Browser.open`).
The Claude badge is an unofficial vector approximation; check Anthropic's brand guidelines before publishing.

## Desktop / Android builds (GitHub Actions)

`.github/workflows/build.yml` builds standalone apps (an optional alternative to the browser).
Run it from the Actions tab ("Run workflow") or push a tag such as `v1.0.0` to also publish all files to a GitHub Release.
Keep `version` in `package.json` equal to the tag (currently `v0.0.1`) and run `python3 tools/build_about.py` after changing it.
Commit the generated `ads.js` (run `python3 tools/build_ads.py` after changing ads) and `build/icons/` (run `python3 tools/make_icons.py` after changing `build/icon.png`).

## OpenWrt (LuCI: Services > MonoWordTest)

The router only serves the static files; the game runs in the browser of the PC/phone that opens LuCI.
That is why one package fits **every** OpenWrt CPU architecture (it is built as arch `all` / `noarch`).
It needs `luci-base` (a working LuCI web interface). Installed size is about 720 KB (package about 280 KB).

| Your OpenWrt | Package manager | Install |
|--------------|-----------------|---------|
| 24.10 and older | opkg | `opkg install /tmp/luci-app-monowordtest_1.0.0-r1_all.ipk` |
| 25.12 and newer | apk | `apk add --allow-untrusted /tmp/luci-app-monowordtest-1.0.0-r1.apk` |

Copy the file to the router first, e.g. `scp -O luci-app-monowordtest_1.0.0-r1_all.ipk root@192.168.1.1:/tmp/`
(`-O` is needed when the router has no sftp-server). Then open LuCI -> **Services -> MonoWordTest**
(press Ctrl+F5 or log in again if the entry is missing). Remove with `opkg remove luci-app-monowordtest`
or `apk del luci-app-monowordtest`.

If the menu entry does not appear: `rm -rf /tmp/luci-* && /etc/init.d/rpcd restart`.

How it is built: `openwrt/build.sh` stages the files (`openwrt/files/` + the web files from the repo root) and
packs them: the `.ipk` with OpenWrt's own `ipkg-build` script (pinned to the v24.10.0 tag), the `.apk` with
`apk mkpkg` (apk-tools 3, the tool OpenWrt uses). Packages are unsigned, hence `--allow-untrusted` for apk.
The page is served from `/www/luci-static/resources/monowordtest/`, the LuCI view is
`/www/luci-static/resources/view/monowordtest/main.js` (an iframe), the menu entry is in `/usr/share/luci/menu.d/`.

## Android: hidden Activity

Besides `io.github.monowordtest.MainActivity` the APK contains `io.github.monowordtest.SecretActivity`: no launcher entry,
nothing in the app opens it, but it is exported, so an activity-launcher app can start it. It shows a "secret word of the day"
(the same word all day) from the built-in dictionary. Source: `android-extra/`.

## Download size

Electron packages contain a whole Chromium (about 70-100 MB each); the Android APK uses the phone's WebView (about 5 MB).
`electronLanguages` in `package.json` keeps only the needed Chromium locales, and artifacts are kept for 3 days
(GitHub's free artifact storage is only 500 MB). Download finished builds from the GitHub Release (tag `vX.Y.Z`).

## Android: Exit button and hidden Activity

`android-extra/MainActivity.java` replaces Capacitor's default `MainActivity` during the CI build and adds `window.MWTAndroid.exit()`
(closes the task); the page's **Exit** button uses it first, then the Capacitor App plugin, then `window.close()`.
The same job copies `SecretActivity` into the APK, adds it to the manifest, checks that `index.html`, `dictionary.js`, `about.js`,
`ads.js`, `sounds.js` and `secret.html` really are inside the app assets, and prints the Activities found in the finished APK
(step "Show which Activities the APK really contains").

Do not run `.py` files with `sh` in a shell that has no header: `import sys` would be executed by ImageMagick's `import`
(a screenshot tool) and writes a huge file called `sys`. The tools in `tools/` now carry a header that makes `sh tools/x.py` work.
